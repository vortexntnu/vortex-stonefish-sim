# Waypoint marker in Stonefish (visible in the sim window, not in camera feeds)

## Context
We want to see where the drone is heading when a waypoint is sent. The marker has to show up in the Stonefish GUI window. It must **not** show up in simulated camera images, because perception runs on those images.

## Key finding: how to hide it from cameras
Stonefish has no per-camera visibility mask. Any real object you put in a `.scn` file (a sphere, a box, and so on) is drawn by every `ColorCamera`/`DepthCamera`/`SegmentationCamera`. So **a marker cannot be a scenario object.**

Stonefish does have a "helper" overlay pass that runs **only for the main trackball view**:
- `~/stonefish/Library/src/graphics/OpenGLPipeline.cpp:711`: `if(camera->getType() == ViewType::TRACKBALL) { ... DrawHelpers(); }`
- Sensor cameras only call `DrawObjects()` (`OpenGLPipeline.cpp:206`), which draws only `RenderableType::SOLID`.

So if we push a non-SOLID `Renderable` into the drawing queue and draw it in `DrawHelpers()`, it shows in the GUI and cameras never see it. This is the same mechanism Stonefish already uses for coordinate frames, joint axes and sensor frustums.

## Where the waypoint comes from
`vortex-auv/mission/waypoint_manager` already publishes the active waypoint:
- Topic: `/<ns>/debug/waypoint` (`vortex_msgs/msg/Waypoint`, QoS best_effort)
- Enabled by the waypoint_manager param `debug.publish_mode` set to `timer` or `on_new_waypoint` (`waypoint_manager_ros.cpp:75-97`)
- `Waypoint.pose` is in odom NED. With `mock_odom:=true`, sim odom is the Stonefish world NED frame, so we can use the position directly.

## Changes

### 1. Stonefish fork (`~/stonefish`, vortexntnu/stonefish), a small core patch
- `Library/include/graphics/OpenGLDataStructs.h`
  - Add `DEBUG_MARKER` to `enum class RenderableType`.
  - Add `bool showMarkers;` to `HelperSettings` (default `true`).
- `Library/src/graphics/OpenGLPipeline.cpp`, `DrawHelpers()`: add
  ```cpp
  if(hSettings.showMarkers)
      for(auto& r : drawingQueueCopy)
          if(r.type == RenderableType::DEBUG_MARKER)
              content->DrawPrimitives(PrimitiveType::LINES, r.points, glm::vec4(0.f,1.f,0.f,1.f), r.model);
  ```
  (Optionally use `content->DrawEllipsoid(r.model, glm::vec3(0.15f), color)` for a sphere.)
- `Library/include/core/SimulationManager.h:129`: make `UpdateDrawingQueue()` `virtual`. It is called from `GraphicalSimulationApp.cpp:627,1040`.
- Rebuild and reinstall: `cd ~/stonefish/build && make -j4 && sudo make install`

### 2. stonefish_ros2 fork (`~/ros2_ws/src/stonefish_ros2`)
- `include/stonefish_ros2/ROS2SimulationManager.h`: add
  - `void UpdateDrawingQueue() override;`
  - a `rclcpp::Subscription<vortex_msgs::msg::Waypoint>::SharedPtr waypointSub_;`
  - `std::mutex waypointMtx_; std::optional<glm::vec3> waypoint_;`
- `src/stonefish_ros2/ROS2SimulationManager.cpp`:
  - In `BuildScenario()` (line 165), create the subscription on `nh_` with the topic from the ROS param `waypoint_marker_topic` (default `/orca/debug/waypoint`) and best_effort QoS. The callback stores the position under the mutex.
  - `UpdateDrawingQueue()`: call `SimulationManager::UpdateDrawingQueue()`, then, if a waypoint is set, build a `Renderable{type=DEBUG_MARKER, model=translate(waypoint)}` with `points` forming a 3-axis cross (±0.3 m), and call `getGLPipeline()->AddToDrawingQueue(r)`.
  - Optionally add a second renderable: a line from the drone's base pose to the waypoint, so the heading is obvious.
- `package.xml` / `CMakeLists.txt`: add a `vortex_msgs` dependency. Alternatively, subscribe to `geometry_msgs/PoseStamped` to keep stonefish_ros2 free of Vortex dependencies; then a tiny relay in `stonefish_sim_interface` converts Waypoint to PoseStamped.

### 3. This repo (`vortex-stonefish-sim`)
- `stonefish_sim/launch/simulation.launch.py` (`get_sim_node`): pass the param `waypoint_marker_topic: f"/{namespace}/debug/waypoint"` to the simulator node.
- If we use the PoseStamped variant: add the Waypoint→PoseStamped relay to `stonefish_sim_interface/src/stonefish_sim_interface.cpp`, following the existing subscribe/republish pattern (for example `sonar_info_callback`).

## Verification
1. `ros2 launch stonefish_sim simulation.launch.py scenario:=default`
2. Publish a fake waypoint:
   `ros2 topic pub --qos-reliability best_effort /orca/debug/waypoint vortex_msgs/msg/Waypoint "{pose: {position: {x: 3.0, y: 0.0, z: 1.0}, orientation: {w: 1.0}}}"`
   A green cross should appear 3 m ahead in the GUI window.
3. Open the camera image (`ros2 run rqt_image_view rqt_image_view` on the front camera topic) and point the drone at the marker. The marker must **not** appear in the image.
4. End to end: run waypoint_manager with `debug.publish_mode:=on_new_waypoint`, send a goal, and confirm the marker moves to each new waypoint.
